# 부서 단체방 — 자동 동기화 폐지, 직접 관리 전환 설계

- 작성일: 2026-10-19
- 범위: 메신저 부서방(`chatRooms.type === 'dept'`) — PC·모바일
- 상태: 설계 확정 대기

## 1. 배경

현재 부서방은 `chatRoomRepo.list()`가 호출될 때마다(브라우저별 60초 쓰로틀) 전 부서를 돌며
`users.dept`(부서명) 기준으로 참여자를 **덮어쓴다**. 그 결과:

1. 서류상 소속과 실제 함께 일하는 사람이 다를 때(예: 표면상 연구팀, 실질 개발팀) 방에 둘 수 없다. 초대해도 다음 동기화에서 빠진다.
2. 부서 이동 후 기존 부서방을 계속 써야 하는 경우(인수인계 등)를 지원할 수 없다.
3. 이름 포함 매칭(`r.name.includes(dept.name)`) 때문에 사용자가 만든 일반 단체방이 부서방으로 바뀌어 참여자·이름이 덮어써질 수 있다.
4. PC는 관리자가 부서방을 삭제할 수 있으나(`MessengerPanel.tsx` `canDelete = isAdmin`) 모바일은 막혀 있다. 삭제된 부서방은 동기화가 지움 표시를 풀지 않아 영구히 숨는다.
5. 부서 삭제 시 부서방이 동기화 대상에서 빠진 채 `dept` 타입으로 남아, 남은 참여자가 나갈 수도 없다.
6. 접속한 모든 브라우저가 각자 동기화·저장한다.

부서명 변경은 `DepartmentScreen`이 소속 계정의 `users.dept`를 함께 바꾸고, 방은 `deptId`로 찾으므로 현재도 정상 동작한다.

## 2. 결정 사항 (사용자 확정)

- 부서방 참여자는 **직접 관리**한다. 자동으로 참여자를 덮어쓰지 않는다.
- 초대·내보내기·나가기는 **참여자 누구나** 할 수 있다 (일반 단체방과 동일).
- 모든 변경은 **로그가 남아야** 한다 → **방 안 시스템 메시지**로 남긴다. 별도 감사 로그 컬렉션은 만들지 않는다.
- 겸직(`departmentMembers`) 연동, 유지 참여자(`keepMembers`) 칸은 도입하지 않는다.

## 3. 동작 규칙

| 상황 | 동작 | 시스템 메시지 |
|---|---|---|
| 부서방이 없는 부서에 사용 중 계정이 1명 이상 | 방을 **한 번만** 개설, 그 시점 부서원을 참여자로 | `{부서명} 부서 단체방이 개설되었습니다.` (기존 문구) |
| 부서방이 이미 있음 (지운 방 포함) | 참여자 건드리지 않음. 빈 방이 되어도 재개설 안 함 | — |
| 부서명 변경 | 방 이름을 `[{새 부서명}] 부서 단체방`으로 | `부서명 변경으로 방 이름이 [{새 부서명}] 부서 단체방으로 바뀌었습니다` |
| 초대 / 내보내기 / 나가기 | 일반 단체방과 동일 | 기존 문구 그대로 |
| 방 이름 직접 변경 | **불가** (부서명을 따름) | — |
| 관리자 방 삭제 | **불가** (PC·모바일 모두) | — |
| 인명관리 퇴직 처리 | 그 사람을 모든 부서방에서 제외 | `퇴직 처리로 {이름}님이 제외되었습니다` |
| 부서관리 부서 삭제 | 그 부서방을 일반 단체방으로 전환(`type: 'group'`, `deptId: null`), 이름·참여자·대화 유지 | `부서 삭제로 일반 단체방으로 전환되었습니다` |

시스템 메시지는 `senderId: ''`, `type: 'system'`으로 기존 단체방 메시지와 같은 방식이며, 사용자가 지울 수 없다.

## 4. 변경 위치

### 4.1 데이터 계층 — `src/data/chatRoom/chatRoom.repo.ts`
- **확인된 사실 (2026-10-19, 운영·개발 DB 읽기 전용 조회)**: Appwrite `chatRooms` 컬렉션에 `deptId` 칸이 없고, 저장 어댑터(`toAttrs`/`fromRow`)도 이 값을 다루지 않는다. 그래서 모든 부서방의 `deptId`가 비어 있고, 현재 동기화는 60초마다 부서방 전부를 "deptId 다름"으로 판단해 다시 저장하고 있다. 운영의 부서방 9개는 모두 방 ID `RM-DEPT-{부서ID}`로 부서 9개와 1:1 대응하며, 삭제된 방·주인 없는 방은 없다.
  → 부서 판별은 **방 ID에서 부서 ID를 꺼내는 방식**(`RM-DEPT-{id}`/`ROOM-DEPT-{id}`)으로 한다. DB 칸은 추가하지 않는다.
- `list()` 안의 동기화를 **개설 전용**으로 축소한다.
  - 기존 방 찾기: 방 ID `RM-DEPT-{id}`/`ROOM-DEPT-{id}` 일치(타입·삭제 여부 무관 — 같은 ID 방이 있으면 절대 새로 만들지 않아 덮어쓰기를 막는다) → `deptId` 일치. **이름 매칭 단계 삭제.**
  - 찾으면 아무것도 쓰지 않는다. 단, 방 이름이 표준 이름과 다르면 이름만 고친다(부서명 변경 반영). 이름 변경 시 위 시스템 메시지를 함께 남긴다.
  - 없고 사용 중 부서원이 있으면 개설(현재 로직 유지).
  - 60초 쓰로틀은 유지한다. 이제 쓰기는 개설·이름 변경 때만 일어난다.
- 판정 로직은 순수 함수로 분리해 테스트한다: `planDeptRoomSync(depts, users, rooms) → { create: ChatRoom[]; rename: {roomId, name}[] }` (위치: `src/domain/chatRoom/deptRoom.ts`).
- 추가 메서드:
  - `removeMemberFromDeptRooms(userId)` — 퇴직용. 해당 사용자가 들어 있는 살아있는 `dept` 방에서 제외하고, 제외된 방 ID 목록을 돌려준다.
  - `detachDeptRoom(deptId)` — 부서 삭제용. `type: 'group'`, `deptId: null`로 바꾸고 전환된 방 ID 목록을 돌려준다(없으면 빈 배열).

### 4.2 기능 계층 — `src/features/chat/useChatRooms.ts`
- 시스템 메시지 생성 코드가 훅마다 복사돼 있으므로 `appendSystemMessage(roomId, text)` 도우미로 모은다 (기존 초대·나가기·내보내기·삭제 훅도 이것을 사용).

- 방 이름 변경: `group`만 (현재와 동일, dept 제외 유지).

### 4.4 화면 — 모바일 `src/mobile/MobileChatThread.tsx`, `src/mobile/MobileChatList.tsx`
- 나가기·초대 조건을 PC와 동일하게 `group || dept`. (모바일은 일반 단체방도 내보내기가 없으므로 내보내기는 PC 전용 유지.)
- "🏢 부서방은 인사이동 시 자동 관리됩니다" 항목 삭제.

### 4.5 퇴직 — `src/features/employeeProfile/useRetirement.ts`

- 메신저 쪽 실패가 퇴직 처리 자체를 실패시키지 않도록 `try/catch`로 감싸고 경고만 남긴다(계정·인사 처리가 본 작업).

### 4.6 부서 삭제 — `src/modules/base/department/DepartmentScreen.tsx`

- 삭제 확인 문구에 "부서 단체방은 일반 단체방으로 바뀝니다"를 덧붙인다.

## 5. 데이터 / 배포

- **DB 구조 변경 없음.** 새 칸·새 컬렉션 없음 → 운영 DB 사전 작업 없음.
- 기존 방의 참여자는 그대로 두고, 배포 이후부터 직접 관리로 바뀐다.
- 착수 전 운영 DB **읽기 전용** 확인 (2026-10-19 완료 — 1·2·3 모두 해당 없음. 개발 DB에만 시험용 잔여 방 2개가 있으며 새 규칙에서 일반 권한을 가진 부서방으로 남을 뿐 문제없음):
  1. 모든 `type: 'dept'` 방에 `deptId`가 있는지 — 없으면 이름 매칭 삭제 후 중복 개설될 수 있으므로, 해당 방은 작업 전에 보고하고 처리 방법을 사용자와 정한다.
  2. 지움 표시가 있는 부서방 존재 여부 — 있으면 되살릴지 사용자에게 묻는다 (기본: 그대로 둠).
  3. 이미 삭제된 부서에 묶인 `dept` 방 존재 여부 — 있으면 일반 단체방 전환 여부를 사용자에게 묻는다.

## 6. 테스트

- 단위(`src/domain/chatRoom/deptRoom.test.ts`):
  - 방 없는 부서 + 부서원 있음 → 개설, 부서원 없음 → 개설 안 함
  - 방 있음(참여자 달라도) → 참여자 변경 없음
  - 지운 방 있음 → 재개설 안 함
  - 부서명 변경 → 이름만 변경 대상
  - 이름에 부서명이 들어간 일반 단체방 → 건드리지 않음
- 화면(개발 서버, PC·모바일): 부서방 초대·내보내기·나가기 후 시스템 메시지 확인, 관리자 삭제 메뉴 미노출, 다음 동기화 뒤에도 참여자 유지.
- `npx tsc --noEmit`, 전체 테스트, `npm run build`.
