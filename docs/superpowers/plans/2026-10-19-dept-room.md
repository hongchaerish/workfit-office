# 부서 단체방 직접 관리 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 부서방 참여자를 자동으로 덮어쓰던 동기화를 없애고, 참여자 누구나 초대·내보내기·나가기를 할 수 있게 하며, 모든 변경을 방 안 시스템 메시지로 남긴다.

**Architecture:** 판정 로직(어떤 부서방을 개설/이름변경할지)을 순수 함수 `planDeptRoomSync`로 분리하고, 저장소(`chatRoomRepo.list`)는 그 결과만 적용한다. 부서 판별은 방 ID(`RM-DEPT-{부서ID}`)로 한다(Appwrite에 `deptId` 칸이 없음). 퇴직·부서 삭제는 해당 화면 흐름에서 저장소 메서드를 호출해 처리한다.

**Tech Stack:** React + TanStack Query, zod, Appwrite(node-appwrite 아님 — 브라우저 SDK), 테스트는 `node:test` + `npx tsx --test`.

**Spec:** `docs/superpowers/specs/2026-10-19-dept-room-design.md`

## Global Constraints

- DB 구조 변경 없음 — 새 칸·새 컬렉션 금지. `chatRooms` 저장 어댑터(`toAttrs`/`fromRow`)에 `deptId` 추가 금지.
- 기존 방의 참여자를 자동으로 바꾸는 코드 금지 (퇴직 제외만 예외).
- 같은 ID의 방이 이미 있으면(타입·삭제 여부 무관) 새 방을 만들지 않는다 — Appwrite `save`는 upsert라 덮어쓰기가 된다.
- 시스템 메시지는 `senderId: ''`, `type: 'system'`, ID `${roomId}-sys-${Date.now()}` (기존 형식 그대로 — Appwrite ID 36자 제한).
- 메시지 문구(정확히):
  - 개설: `{부서명} 부서 단체방이 개설되었습니다.` (lastMessage 문구, 기존 그대로)
  - 이름 변경: `부서명 변경으로 방 이름이 [{새 부서명}] 부서 단체방으로 바뀌었습니다`
  - 퇴직: `퇴직 처리로 {이름}님이 제외되었습니다`
  - 부서 삭제: `부서 삭제로 일반 단체방으로 전환되었습니다`
- 표준 방 이름: `[{부서명}] 부서 단체방`.
- 결재 데이터(`approvalDocs`, `approvalForms`) 접근 금지.
- 모든 답변·주석은 한국어.

## Review Focus

1. 부서 ID가 바뀌지 않은 채 부서명만 바뀐 경우 → 참여자는 그대로, 이름만 바뀌고 메시지 1건. (Task 1 테스트)
2. 같은 ID(`RM-DEPT-D110`)의 **일반 단체방**이 이미 있는데 D110 부서가 생긴 경우 → 그 방을 덮어쓰지 않는다(개설·이름변경 모두 안 함). (Task 1 테스트)
3. 참여자가 모두 나가 빈 부서방 → 다음 동기화에서 재개설·참여자 복원 없음. (Task 1 테스트)
4. 퇴직 처리 중 메신저 쪽 저장이 실패 → 퇴직 처리 자체는 성공으로 끝난다. (Task 4 — try/catch, 수동 확인)
5. 이미 삭제된(지움 표시) 부서방에 퇴직자가 있는 경우 → 건드리지 않는다. (Task 2 테스트)

```ts
import { chatRoomSchema, type ChatRoom } from './schema';

/**
 * 부서 단체방 판정 — 순수 함수. ([[docs/superpowers/specs/2026-10-19-dept-room-design.md]])
 *
 * 부서방은 처음 한 번만 자동 개설하고, 이후 참여자는 사람이 직접 관리한다.
 * 자동으로 하는 일은 '방 없는 부서에 개설'과 '부서명 변경 시 방 이름 따라가기' 둘뿐이다.
 * Appwrite chatRooms 에는 deptId 칸이 없으므로 부서는 방 ID(`RM-DEPT-{부서ID}`)로 판별한다.
 */
const DEPT_ROOM_ID = /^(?:RM|ROOM)-DEPT-(.+)$/;

export function deptRoomId(deptId: string): string {
  return `RM-DEPT-${deptId.replace(/[^a-zA-Z0-9_-]/g, '')}`;
}

export function deptRoomName(deptName: string): string {
  return `[${deptName}] 부서 단체방`;
}

/** 부서방이면 그 부서 ID, 아니면 null. */
export function deptIdOfRoom(room: Pick<ChatRoom, 'id' | 'type' | 'deptId'>): string | null {
  if (room.type !== 'dept') return null;
  return room.deptId ?? DEPT_ROOM_ID.exec(room.id)?.[1] ?? null;
}

interface PlanInput {
  depts: { id: string; name: string }[];
  users: { id: string; dept: string; status: string }[];
  rooms: ChatRoom[];
  now: string;
  pickColor: (roomId: string) => string;
}

export interface DeptRoomPlan {
  create: ChatRoom[];
  rename: { roomId: string; name: string }[];
}

export function planDeptRoomSync({ depts, users, rooms, now, pickColor }: PlanInput): DeptRoomPlan {
  const plan: DeptRoomPlan = { create: [], rename: [] };
  for (const dept of depts) {
    const id = deptRoomId(dept.id);
    // 같은 ID의 방은 타입·삭제 여부와 무관하게 '있음'으로 본다 — 저장이 upsert 라 새로 만들면 덮어쓴다.
    const existing =
      rooms.find((r) => r.id === id || r.id === `ROOM-DEPT-${dept.id}`) ??
      rooms.find((r) => deptIdOfRoom(r) === dept.id);
    const name = deptRoomName(dept.name);

    if (existing) {
      if (existing.type === 'dept' && !existing.deletedAt && existing.name !== name) {
        plan.rename.push({ roomId: existing.id, name });
      }
      continue;
    }

    const members = users.filter((u) => u.dept === dept.name && u.status === '사용').map((u) => u.id);
    if (members.length === 0) continue;
    plan.create.push(
      chatRoomSchema.parse({
        id,
        name,
        type: 'dept',
        deptId: dept.id,
        members,
        color: pickColor(id),
        lastMessage: { text: `${dept.name} 부서 단체방이 개설되었습니다.`, at: now, senderId: 'system' },
        createdAt: now,
        createdBy: 'system',
      }),
    );
  }
  return plan;
}
```

```ts
import { nowLocalIso } from '@/shared/lib/datetime';
import { chatMessageRepo } from './chatMessage.repo';

/**
 * 방 안 시스템 메시지(가운데 캡슐) — 초대·나가기·내보내기·부서방 자동 처리 기록.

export async function appendSystemMessage(roomId: string, text: string): Promise<void> {
  await chatMessageRepo.append({
    id: `${roomId}-sys-${Date.now()}`,
    roomId,
    senderId: '',
    senderName: '',
    text,
    type: 'system',
    attachment: null,
    replyTo: null,
    approvalPayload: null,
    at: nowLocalIso(),
    readBy: [],
    isEdited: false,
    reactions: {},
  });
}
```

```ts
  async removeMemberFromDeptRooms(userId: string): Promise<string[]> {
    const rows = await this.list(undefined, { includeDeleted: true });
    const targets = rows.filter((r) => r.type === 'dept' && !r.deletedAt && r.members.includes(userId));
    for (const r of targets) await this.save({ ...r, members: r.members.filter((m) => m !== userId) });
    return targets.map((r) => r.id);
  },

  /** 부서 삭제 — 그 부서방을 일반 단체방으로 바꾼다(이름·참여자·대화 유지). 바뀐 방 ID 목록을 돌려준다. */
  async detachDeptRoom(deptId: string): Promise<string[]> {
    const rows = await this.list(undefined, { includeDeleted: true });
    const targets = rows.filter((r) => deptIdOfRoom(r) === deptId);
    for (const r of targets) await this.save({ ...r, type: 'group', deptId: null });
    return targets.map((r) => r.id);
  },
```
