# 업무계획 · 캘린더(일정관리) 모듈 기능 보고서

- 작성일: 2026-10-01
- 기준 브랜치: `develop` (`8aef729`)
- 목적: 업무계획 → 캘린더 연동 오류(회의 일정 중복 생성 등)를 고치기 전에 두 모듈의 현재 구조·기능·연동 방식을 정리한다.

---

## 1. 한눈에 보기

| 구분 | 업무계획 | 캘린더(일정관리) |
|---|---|---|
| 메뉴 | 그룹웨어 > 업무계획 (`/gw/work-plan`) | 그룹웨어 > 일정관리 (`/gw/calendar`) |
| 성격 | 사람 × 날짜별 자유 텍스트 한 덩어리(구글시트 대체) | 시간·공개범위·참여자를 가진 일정 |
| 저장 | Appwrite `workPlans` | Appwrite `calendarEvents` |
| 공개 | 공유 범위 개념 없음 — 권한 스코프(본인/부서/전사)로 열람 | `PRIVATE`·`TEAM`·`COMPANY`·`PROJECT` |
| 수정 | 본인 것만(화면에서 통제) | 소유자만(repo에서 강제) |
| 모바일 | `/m/task`(내 업무계획), `/m/work-plan-admin`(현황) | `/m/calendar` |

두 모듈은 **업무계획의 회의·미팅 줄을 캘린더 일정으로 자동 생성**하는 브리지(`workPlanCalendarBridge.ts`)로 연결된다. 반대로 캘린더 일정·전자결재 승인 건은 업무계획 월간표에 **읽기 전용 칩**으로 투영된다.

## 3. 업무계획 기능

### 3.1 데이터 모델
- **한 사람의 하루 = 문서 1건.** `(ownerUserId, date)` 조합이 유일하다(`create`에서 중복이면 `CONFLICT`).
- `content`는 자유 텍스트. 줄 하나가 항목 하나다.
  - `- [ ] 할 일` / `- [x] 완료` : 체크리스트 항목
  - `[회의] 거래처 미팅 (14:00~16:00)` : 태그 + 시간 표기
  - 일반 줄의 완료 상태는 본문 끝 메타 줄 `__c__:0,2`(완료된 줄 번호)로 관리
- **전사 주요 일정**은 `ownerUserId = '__COMPANY__'`인 특수 업무계획으로 저장된다.

### 3.2 월간 계획표 (메인 화면)
- 월을 **주차(월~일) 블록**으로 나누고, 각 블록에 `전사 주요 일정 행` + `임직원 행`이 이어지는 엑셀형 표.
- 공휴일: DB(`holidays`) 우선, DB가 비어 있을 때만 하드코딩 값 사용. 일요일·공휴일은 빨간날 배경.
- 셀 내용 3단계 톤: 오늘 내 칸 / 다른 날 내 칸 / 타인 칸.
- **칩 투영(읽기 전용)**: 각 셀 위쪽에
  - 전자결재 승인 건(휴가·외근·출장) — 기안자 기준
  - 캘린더의 공인 일정(회의·미팅·사내행사) — 소유자 + 참여자 기준. **업무계획에서 만들어진 일정은 제외**(셀 본문과 중복 방지)
- 오늘 주차로 자동 스크롤.

### 3.3 편집·저장
- 셀 클릭 → 셀 안 textarea 인라인 편집(높이 자동 확장). 상단 리본으로 체크박스 삽입·루틴 템플릿·삭제·저장·복사.
- 저장 트리거: **포커스 이탈(blur)** 또는 **Ctrl+Enter**. Esc는 취소.
- 저장 시 기존 체크 상태를 병합(`mergeCheckedMeta`). 줄 수가 바뀌면 체크 상태가 초기화된다.
- 낙관적 동시성: 편집 시작 시점 `updatedAt`과 DB 값이 다르면 `CONFLICT` 오류 → 덮어쓰기 확인.
- 내용을 비우고 저장하면 해당 일자 계획과 연동 캘린더 일정이 삭제된다.
- 체크박스는 **본인 계획만** 토글 가능.

### 3.4 열람 범위 (로스터)
- `resolveWorkPlanScope` / `workPlanPolicy.getScope`
  - 임원·운영자·인사(HR_ADMIN)·권한 부여자: 전사
  - 팀장: 본인 부서원 + 타 부서 팀장급
  - 일반: 본인 부서
- 퇴사자 제외, 테스터 계정 격리(테스터는 본인만, 일반 사용자에게는 테스터 숨김).
- 정렬: 위원장/대표 → 부위원장 → 상무 등 최고위 → 부서 배치순 → 직책 → 직급 → 이름. 겸직(`departmentMembers`) 반영, 대표이사는 업무계획에서 '위원장'으로 표시.
- 부서 필터, 이름·부서 검색.

### 3.5 태그·템플릿
- 기본 태그: 외근·출장, 회의, 보고, 집중, 마감, 교육 (+ 사용자 정의 태그·색상).
- 기본 루틴 템플릿 4종(고객사 미팅 및 협의, 주간 정기 회의, 프로젝트 집중 업무, 월마감 및 정산) + 사용자 정의.
- 저장 위치는 **브라우저 localStorage**(사용자별 키). 다른 PC에서는 공유되지 않는다.

### 3.6 모바일
- `MobileTaskScreen`: 내 업무계획 조회·작성·체크.
- `MobileWorkPlanAdminScreen`: 권한자용 업무 현황(재실 상태 포함).

## 4. 캘린더(일정관리) 기능

### 4.1 데이터 모델
- `eventType`: 일반(GENERAL) · 회의·미팅(MEETING) · 사내행사(COMPANY_EVENT) · 외근·출장(OUTSIDE) · 휴가·부재(VACATION).
- `visibility`: 나만 보기 · 부서 공유(deptId 필수) · 전사 공개 · 프로젝트 공유(projectId 필수). 기본값 `PRIVATE`.
- Appwrite 컬렉션에 `eventType`·`attendeeUserIds` 속성이 없어 **메모 안의 `[CAL_META:{...}]` 태그로 인코딩**해 저장한다.

### 4.2 화면 구성
- **좌측 패널**: 선택한 날의 상세 일정 목록(유형 배지·시간·공유 라벨) + 내 업무계획 To-Do(진행률 게이지, 빠른 추가, 체크).
- **우측**: 월간 컴팩트 달력, 오늘 버튼, 공휴일 표시.
- **탭**: 내 일정 / 팀 일정(열람 범위가 있는 사람만 노출).
  - 내 일정 필터 칩: 전체 관련 일정 · 내 일정 · 참여 회의·일정 · 사내행사 · **부서·프로젝트**
  - 팀 일정: 임원은 부서 선택, 팀장은 맡은 부서 범위. 남의 '나만 보기' 일정은 "비공개 일정"으로 마스킹.
- **사내행사 등록**: 운영자·임원만.
- 알림 링크 `/gw/calendar?date=YYYY-MM-DD`로 진입 시 해당 날짜를 연다.

### 4.3 노출 규칙
- 달력에는 **공인 일정만** 그린다(`isOfficialCalendarEvent`): 전자결재 승인 건, 회의·미팅(유형이 MEETING이거나 제목에 '회의'/'미팅'), 사내행사. 일반 개인 일정은 저장돼도 달력에 나오지 않는다.
- 퇴사자 소유 일정 제외(단, 사내행사·전사 공개는 유지).
- 전자결재 승인 건(휴가·외근·출장)은 저장된 일정이 아니라 **결재 문서에서 즉석 생성**해 합친다. 휴가 사유는 비공개.

### 4.4 등록·수정
- 유형 선택(외근·출장, 휴가는 전자결재 전용이라 신규 등록 불가), 제목, 날짜·종일/시간, 참여자 다중 선택, 공개 범위, 메모.
- 수정·삭제는 **소유자만**(`requireOwned`).
- 날짜·시작 시각이 바뀌면 `reminded`를 초기화해 리마인더를 다시 받게 한다.

### 4.5 알림
- **생성 시 공유 알림** (`notifyRecipients`): 참여자 + 공개 범위 대상자(부서 공유=부서 전원, **전사 공개=재직자 전원**, 프로젝트=참여자)에게 `type:'일정'` 알림 → 모바일 푸시. 수정 시에는 보내지 않는다.
- **리마인더** (`calendar-reminder` Function): 5분마다 실행해 10분 뒤 시작하는 시간 일정의 소유자 + 공유 대상자에게 알림. 공유 대상 규칙은 위와 같다(**전사 공개면 전 직원**).

## 5. 업무계획 ↔ 캘린더 연동

### 5.1 업무계획 → 캘린더 (`syncWorkPlanToCalendar`)
호출 지점:

| 위치 | 시점 |
|---|---|
| `WorkPlanScreen.savePlan` | 셀 저장(blur·Ctrl+Enter), 체크박스 토글 |
| `CalendarScreen` | 좌측 To-Do 체크 토글, 빠른 To-Do 추가 |
| `workPlanRequest.repo` | (미사용 기능) 요청 수락 시 |
| ※ `MobileTaskScreen` | **호출하지 않음** — 모바일에서 쓴 회의는 캘린더에 생기지 않는다 |

동작:
1. 그날 **내가 볼 수 있는** 캘린더 일정을 조회하고, 메모에 `[WP-SYNC:<planId>:<줄번호>]` 태그가 있는 것만 고른다.
2. 업무계획 각 줄 중 **회의/미팅 태그가 있거나 본문에 '회의'·'미팅'이 들어간 줄**을 일정 초안으로 만든다. 시간 표기(`14:00~16:00`, `10:00`)가 있으면 시간 일정, 없으면 종일.
3. 공개 범위: 작성자 부서가 확인되면 `TEAM`(부서 공유), 아니면 `PRIVATE`.
4. **줄 번호로 기존 일정과 짝을 맞춰** 바뀐 것은 수정, 없어진 것은 삭제, 새것은 생성한다.
5. 오류는 콘솔에만 남기고 삼킨다(저장 자체는 성공 처리).

업무계획 삭제(내용 비우기) 시 `cleanupWorkPlanCalendarEvents`가 해당 planId 태그 일정을 모두 지운다.

### 5.2 캘린더 → 업무계획
- 월간표 칩 투영(3.2) — 저장하지 않는 읽기 전용 표시.
- `importCalendarEventsToWorkPlanContent`: 캘린더 일정을 업무계획 본문 줄로 멱등 병합하는 함수(업무계획 유래 일정 제외, 제목 유사도로 중복 방지). 현재 호출하는 화면은 없다.

## 6. 확인된 문제점

| # | 심각도 | 문제 | 근거 |
|---|---|---|---|
| P1 | 높음 | **회의 일정 중복 생성(같은 `:N` 태그 2건 이상)**. 동기화가 같은 계획에 대해 동시에 두 번 돌면 둘 다 "기존 일정 없음"으로 판단해 각각 생성한다. 셀 편집에서 Ctrl+Enter(`onSave`) 후 편집창이 닫히며 blur(`onBlur`)가 다시 저장을 부르고, 체크박스 연타도 같은 경쟁을 만든다. | `WorkPlanTeamMonthlyMatrix.tsx:107-122`, `WorkPlanScreen.tsx:400·426` |
| P2 | 중간 | 줄 번호로 짝을 맞춰서, 줄이 밀리면 **다른 회의의 일정을 덮어쓰거나**(id 유지·내용 교체) 지웠다 다시 만든다. 다시 만들 때마다 공유 알림이 새로 나간다. | `workPlanCalendarBridge.ts:166-195` |
| P3 | 중간 | 공개 범위가 작성자 부서(`TEAM`)로 고정돼 타 부서는 회의를 못 보고, 카드에 "· 부서 공유" 라벨이 붙는다. | `buildShareableCalendarDrafts` |
| P4 | 중간 | 본문에 '회의'·'미팅'이 들어가면 모두 회의로 간주한다(예: "회의록 작성", "미팅 자료 준비"도 일정 생성). | `workPlanCalendarBridge.ts:110` |

### 6.1 개선 보고서(원안) 검토 의견
- **"기존 연동 일정 일괄 삭제 후 재생성"은 P1을 해결하지 못한다.** 동시에 돈 두 동기화가 모두 지우고 모두 만들면 여전히 2건이 남는다.
- **"전사 공개(COMPANY)"와 재생성을 함께 적용하면 알림 폭주가 생긴다.**
  - 생성할 때마다 **재직자 전원**에게 "회의 참여 요청" 알림·푸시가 간다(4.5). 원안대로면 업무계획을 저장할 때마다(체크박스 하나만 눌러도) 회의 일정이 다시 생성되므로 그때마다 전 직원에게 발송된다.
  - 리마인더 Function도 전사 공개 시간 일정이면 **시작 10분 전 전 직원에게** 알린다. 재생성 시 `reminded`가 초기화되므로 재발송 위험도 있다.
- 필터 칩(부서·프로젝트) 삭제와 부서 공유 분기 제거는 기능 결정 사항으로 문제없다.

## 7. 개선 방향 (제안)

1. **동시 실행 차단**: 동기화를 planId별로 직렬화하고, 셀 저장의 Ctrl+Enter→blur 이중 호출을 막는다. (P1)
2. **줄 번호 대신 내용 키로 짝 맞추기**: 시간을 뺀 핵심 문구(정규화 텍스트)로 기존 일정을 찾아 수정 → 줄 순서가 바뀌어도 일정 id 유지, 진짜 새 회의만 생성. (P1·P2)
3. **기존 고스트 정리**: 같은 계획에서 키가 겹치는 일정이 여러 건이면 1건만 남기고 삭제(다음 저장 시 자동 정리). (P1)
4. **전사 공개 + 알림 정책**: 업무계획 유래 회의는 `COMPANY`로 공개하되, 생성 알림과 리마인더 대상은 별도 정책을 둔다(예: 알림 없음 / 소유자·참여자만). (P3, 6.1)
5. **회의 판정 기준 정리**: 태그(`[회의]`·`[미팅]`)가 붙은 줄만 일정으로 만들지 결정. (P4)
6. 캘린더 필터 칩(부서·프로젝트)과 브리지의 `deptId` 분기 삭제. (원안 ③)
7. (선택) 모바일 저장 경로에도 동기화 적용. (P5)
