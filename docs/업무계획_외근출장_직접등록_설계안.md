# 업무계획 외근·출장 직접 등록 설계안

- 작성일: 2026-10-15
- 기준: `develop`
- 선행 문서: `docs/업무계획_회의등록_구현계획서.md`
- 상태: **설계(검토 대기)** — §2의 결정 사항을 확정하면 착수

---

## 1. 목표와 현재 상태

### 현재
- 업무계획 월간표(`WorkPlanTeamMonthlyMatrix.tsx`)의 외근·출장 칩은 **결재 완료(`status === '완료'`) 문서에서만** 만들어진다
  (`extractApprovedSchedules` → `projectedSchedulesMap`).
- 결재 칩은 **누를 수 없다.** 누를 수 있는 칩은 회의 칩(`pItem.event`)뿐이다. 그래서 위치·시간·목적을 보려면 전자결재 문서를 따로 찾아 열어야 한다.
- 캘린더 스키마에 `eventType: 'OUTSIDE'`가 이미 있지만, `CalendarEventModal`은 "외근·출장은 결재로만 등록한다"며 직접 등록을 막아 두었다.

### 목표
1. 결재 없이 **본인이 직접 외근·출장 카드를 등록·수정·삭제**할 수 있다.
2. 결재 완료 건과 직접 등록 건 **모두** 업무계획에서 누르면 **상세 정보**(구분, 기간·시간, 장소, 목적, 동행자, 교통수단, 연락처, 출처)가 뜬다.
3. 두 출처를 **한눈에 구분**할 수 있다(결재 완료 ✓ / 직접 등록).
4. 기존 결재 문서(`approvalDocs`)와 서식(`approvalForms`)은 **읽기만** 한다(CLAUDE.md §2).

### 성공 기준
- A가 업무계획 자기 칸에서 [외근 등록]으로 "10/20 14:00~17:00 OO전자 미팅"을 넣으면, A의 10/20 칸에 외근 칩이 뜨고 전 직원이 볼 수 있다.
- 그 칩이나 결재 완료 외근 칩을 누르면 같은 모양의 상세 패널이 열린다. 결재 건에는 [결재 문서 보기]가 있다.
- 직접 등록 건은 **근태 판정에 영향을 주지 않는다**(§2-b 기본안).

## 2. 결정 사항 (검토 필요)

| # | 항목 | 권고안 | 다른 안 |
|---|---|---|---|
| a | 저장 위치 | **새 컬렉션 `outsideWorks`** (§3) | 캘린더 일정(`calendarEvents`)에 `OUTSIDE`로 저장 |
| b | 근태 판정 반영 | **반영 안 함** — 결재 완료 건만 지각·미출근 면제 근거. 직접 등록 건은 "알림용" | 반영함(부정 사용 여지가 큼) |
| c | 재실 상태(프로필 점) 반영 | **반영함** — 시간대 안이면 '외근 중' 표시. 근태와 달리 정보 표시일 뿐이라 위험이 적다 | 반영 안 함 |
| d | 공개 범위 | **전사 공개 고정** — 업무계획이 원래 전사 공개(`workPlan/schema.ts` 주석) | 부서 공유 선택 가능 |
| e | 결재 진행 중(`진행`) 문서 | **표시 안 함**(지금과 같음). 필요하면 2차에 '결재 중' 흐린 칩으로 추가 | 지금부터 표시 |
| f | 같은 날 결재 건과 직접 등록 건이 겹칠 때 | **둘 다 표시**하되, 직접 등록 카드에서 [결재 건과 연결]을 누르면 직접 등록 칩을 숨긴다(§5) | 자동 병합(오판 위험) |
| g | 캘린더 화면 표시 | **표시함** — 결재 건과 같은 규칙으로 캘린더에도 투영 | 업무계획에만 표시 |
| h | 수정·삭제 권한 | **본인만**(업무계획과 같은 규칙). 관리자 대리 등록은 하지 않음 | 팀장 대리 등록 |

## 3. 데이터 모델 — `outsideWorks` (신규, 기존 데이터와 격리)

캘린더 일정 대신 새 컬렉션을 권하는 이유:
- 캘린더 일정은 **하루 1건**(`date` 하나)이다. 3일 출장을 넣으면 3건이 생기고 수정·삭제가 번거롭다. 외근·출장은 **기간**이 기본이다.
- 장소·목적·동행자·교통수단처럼 외근에만 있는 필드를 캘린더에 넣으면 회의·일반 일정 스키마가 지저분해진다.
- `isOfficialCalendarEvent`가 `eventType === 'OUTSIDE'`를 "결재 공인 일정"으로 보고 있어, 섞으면 출처 판별이 흐려진다.

```ts
// src/domain/outsideWork/schema.ts
export const OUTSIDE_WORK_CATEGORIES = ['OUTSIDE', 'TRIP'] as const;   // 외근 / 출장
export const OUTSIDE_WORK_SUBTYPES = {
  OUTSIDE: ['종일 외근', '오전 외근', '오후 외근', '시간 외근'],
  TRIP: ['국내출장', '해외출장'],
} as const;                                                          // 결재 서식 값과 같은 말을 쓴다(statusDisplay 재사용)

export const outsideWorkSchema = z.object({
  id: z.string().regex(/^OW-\d{8}-\d{4}$/),
  ownerUserId: z.string().min(1),
  category: z.enum(OUTSIDE_WORK_CATEGORIES),
  subType: z.string().min(1),
  startDate: dateSchema,
  endDate: dateSchema,                 // startDate 이상
  allDay: z.boolean(),
  startTime: timeSchema.nullable(),    // allDay면 null (캘린더와 같은 규칙)
  endTime: timeSchema.nullable(),
  destination: z.string().trim().min(1).max(200),   // 필수 — 상세 보기의 핵심
  purpose: z.string().trim().max(500).default(''),
  companionUserIds: z.array(z.string()).default([]),
  transportation: z.string().trim().max(50).default(''),
  contact: z.string().trim().max(50).default(''),
  memo: z.string().trim().max(2_000).default(''),
  /** 같은 일정의 결재 문서를 나중에 연결하면 그 id. 연결되면 업무계획에선 결재 칩만 보인다. */
  linkedApprovalDocId: z.string().nullable().default(null),
  createdAt, updatedAt,
});
```

- Appwrite: `scripts/appwrite-schema.ts`에 `outsideWorks` 컬렉션 추가(신규 생성만, 기존 컬렉션 변경 없음).
  권한은 읽기 전원, 쓰기는 문서 단위로 본인(`user:<id>`)만.
- 인덱스: `startDate`, `endDate`, `ownerUserId` — 월간표는 `endDate >= 월초 AND startDate <= 월말`로 읽는다.
- repo: `src/data/outsideWork/outsideWork.repo.ts` (list(range) / create / update / remove), 훅 `src/features/outsideWork/useOutsideWorks.ts`.

## 4. 공통 표시 모델 — 두 출처를 하나로

화면마다 결재 건과 직접 등록 건을 따로 다루지 않도록, 순수 함수 하나로 합친다.

```ts
// src/domain/outsideWork/view.ts
export interface OutsideScheduleView {
  key: string;                         // 'appr-<docId>' | 'self-<id>'
  source: 'APPROVAL' | 'SELF';
  ownerUserId: string;
  category: 'OUTSIDE' | 'TRIP';
  subType: string;
  startDate: string; endDate: string;
  startTime?: string; endTime?: string;
  destination?: string; purpose?: string;
  companions?: string;                 // 결재는 문자열, 직접 등록은 id → 이름으로 변환
  transportation?: string; contact?: string; memo?: string;
  approval?: { docId: string; docNo: string; docTitle: string };  // source === 'APPROVAL'
  selfId?: string;                                                  // source === 'SELF'
}

fromApproval(s: StandardScheduleInfo): OutsideScheduleView   // LEAVE는 제외
fromSelf(w: OutsideWork, userName: (id) => string): OutsideScheduleView
mergeOutsideSchedules(approved, self): OutsideScheduleView[]  // linkedApprovalDocId가 있는 self는 제외
```

- 결재 쪽 값은 이미 있는 `extractScheduleInfo`가 뽑아 준다(destination·purpose·transportation·emergencyContact·companions·startTime·endTime·subType). **결재 문서는 읽기만 한다.**
- 테스트: `view.test.ts` — 결재/직접 등록 변환, 연결된 건 숨김, 기간 겹침, 휴가 제외.

## 5. 화면

### 5-1. 업무계획 월간표 (`WorkPlanTeamMonthlyMatrix.tsx`)
- `projectedSchedulesMap`의 결재 외근·출장 부분을 `mergeOutsideSchedules` 결과로 바꾼다. 휴가·회의 칩은 지금 그대로 둔다.
- 칩 모양:
  - **결재 완료**: 지금 색(`STATUS_TONES`) + 앞에 `✓` 표시. 툴팁 "결재 완료 · 눌러서 상세 보기"
  - **직접 등록**: 같은 색에 **점선 테두리**. 툴팁 "직접 등록(미결재) · 눌러서 상세 보기"
  - 라벨은 지금 규칙 그대로: `[외근] 오후 외근 (OO전자)` + 오른쪽에 시간
- **모든 외근·출장 칩을 누를 수 있게** 한다(`e.stopPropagation()`으로 칸 편집은 안 열리게 — 회의 칩과 같은 방식).
- 등록 진입점 두 곳:
  1. 상단 툴바에 **[+ 외근·출장]** 버튼 → 오늘 날짜로 등록 모달
  2. **내 칸**에 마우스를 올리면 오른쪽 위에 작은 `🚗+` 아이콘 → 그 날짜로 등록 모달
     (칸 클릭은 지금처럼 업무계획 편집이라 그대로 둔다)

- `CalendarScreen` / `MobileCalendarScreen`의 `scheduleEvents` 투영에 직접 등록 건을 더한다(id `CAL-SELF-OW-…`, 제목 앞에 `[외근]`, 결재 건과 같은 색 + 점선).
- `MobileTaskScreen`(모바일 업무계획)에도 같은 칩·상세·등록 모달을 붙인다 — 회의 등록 때 결정(e)과 같은 원칙.

## 6. 근태·재실과의 경계

| 사용처 | 결재 완료 건 | 직접 등록 건 |
|---|---|---|
| 업무계획 칩·상세 | ✅ | ✅ |
| 캘린더 | ✅ | ✅ (§2-g) |
| 재실 상태(`resolvePresence`) | ✅ 외근 | ✅ 외근 (§2-c) |
| 근태 판정(`approvalDayIndex`, `useCommuteEvaluation`) | ✅ 면제 근거 | ❌ **반영 안 함** (§2-b) |
| 근태 매트릭스 표시 | ✅ | 반영하려면 "참고" 회색 표기만(2차) |

`approvalDayIndex` / `extractApprovedSchedules`는 **수정하지 않는다** — 직접 등록 건이 근태로 새어 들어갈 길을 구조적으로 막는다.

## 8. 위험과 대응
- **결재 회피 수단으로 쓰일 수 있음** → 근태에 반영하지 않고, 상세·칩에 "직접 등록(미결재)"을 항상 표시한다(§2-b).
- **중복 표시**(직접 등록 후 결재도 올림) → [결재 건과 연결] + 등록 모달의 같은 날 경고(§2-f).
- **월간표 쿼리 증가** → 월 범위 1회 조회, 인덱스로 처리. 결재 전건 조회(`useAllApprovals`)는 지금과 같다.
